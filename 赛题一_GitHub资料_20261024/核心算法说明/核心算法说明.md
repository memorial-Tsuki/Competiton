# 核心算法说明：参考额度锚定与窗口峰值混合模型

## 1. 研究目标与评分对象

目标是对当前申请客户进行还款困难风险排序，同时隔离“仅授信额度提高”带来的机械性使用率变化。输出是当前申请风险的预测概率（PD）、分数和风险等级；它不是自动授信结论、逐月历史违约结果或提额的因果效应。

## 2. 数据处理

1. 以 `SK_ID_CURR` 去重，保留每名客户一行；样本要求月 -1 存在有效、活跃、正额度且非负余额的信用卡。
2. 当前卡状态取月 -1；行为历史取月 -6 至 -2，避免把当前快照重复写入历史特征。
3. 早期申请仅使用 `DAYS_DECISION <= -1`；还款计划按到期日 -365 至 -1 聚合。冲突日期、冲突计划金额、多版本计划和非正计划金额不进入短缺计算。
4. 在训练集拟合中位数填补、缺失指示、标准化和类别编码；验证、校准、测试只使用训练期学习到的处理器。
5. 最终主模型使用 41 个清洗字段；外部评分属于特征之一，另保留去外部评分消融，不把其当作模型有效性的唯一依据。

## 3. 参考额度锚定

对每名客户记录审核参考额度 L*。当仅有额度变化、其余输入不变时，模型仍以 L* 重算额度、使用率和额度收入比等额度敏感变量。因此“纯提额评分不变”是输入构造与计算口径的结构性质，不是对真实提额风险因果效应的证明。

## 4. 窗口峰值逾期特征

将当前普通逾期、当前严重逾期和历史最大逾期映射为：

`r = ln(1 + min(max(历史峰值, 当前普通逾期, 当前严重逾期), 30))`

模型只对突破历史峰值的新增恶化作出额外响应；30 天起封顶。该口径防止已存在的历史高逾期被当前较小逾期重复放大，但也带来明显边界：超过 30 天的进一步恶化无法区分。

## 5. 最终 C 组模型

最终冻结模型文件为 `核心代码/评分界面/model_runtime/models/20260923_rolling_hybrid.joblib`，SHA-256：`70576bba02e2207188626878673a1bdd8409bc45180f8e637f258536d12694cf`。

1. 主分量：参考额度锚定、带方向约束的 HistGradientBoostingClassifier。学习率 0.05，15 个叶节点，160 次迭代，L2 正则 10，最小叶节点 120；使用窗口峰值后的逾期特征。
2. 辅分量：带符号约束的逻辑回归，岭系数 0.001；同样使用窗口峰值特征。
3. 混合：`p_raw = 0.75 × p_tree + 0.25 × p_lr`。0.25 的权重由验证集预设门槛下选择，测试标签没有参与权重选择。
4. 校准：独立校准集逻辑校准，`logit(PD) = 0.9594906018 × logit(p_raw) - 0.0991217608`。

## 6. 评分刻度与等级

评分公式为：`Score = clip(600 + 40 / ln(2) × (-ln(19) - logit(PD)), 300, 850)`。分数越高表示预测风险越低；在其他条件相同下，好坏比翻倍对应约 40 分。风险等级及复核提示由 `核心代码/评分界面/scoring.py` 的冻结规则生成。

## 7. 证据边界

已有证据包括：固定参考额度下纯提额情景的零分差结构核验、统一测试集上的区分度与校准指标、重复划分范围、观察到的两期逾期变化核验。尚未得到的证据包括时间外验证、真实提额因果标签、生产部署后的漂移监控和策略收益验证。
